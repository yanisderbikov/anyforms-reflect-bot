# anyforms-reflect-bot

Telegram-бот ежедневных рефлексий: ребята пишут отчёт за день в общую группу, бот
складывает отчёты в Google-таблицу, по будням в 18:00 напоминает, а в 20:00 тегает
тех, кто не сдал.

## Как работает

**Таблица.** Если листов нет, бот создаёт их сам.

- `Аккаунты`: `Username` | `Имя`, например `@ivan_bel` | `Белорус`. Пишем и пингуем
  только тех, кто есть в этом листе.
- `Настройки`: `Ключ` | `Значение`; строка `chat_id` — id общей группы.
- По листу на месяц (`Октябрь 2026`, …): `Кто` | `Когда` | `Отчёт` | `Пометка` |
  `Username` | `message_id`. Последние две колонки служебные: по ним бот после
  рестарта понимает, кто сдал сегодня, и ловит правки. Если человек не сдал отчёт,
  строки нет.

**Кеш.** При холодном старте бот загружает таблицу целиком. Пока она недоступна, он
молчит и повторяет попытку раз в 30 секунд. Дальше всё живёт в памяти. `/add` и
`/remove` пишут сразу и в таблицу, и в кеш. Если таблицу поправили руками — `/sync`.

**Отчёт** — первое за день (МСК) сообщение человека из списка в общей группе длиной
от `MIN_REPORT_CHARS` символов. Сдать можно в любое время, не только после
напоминания. Остальные сообщения за день — обычная переписка. Для фото берётся
подпись. Записанный отчёт бот отмечает реакцией 👍. Если отчёт отредактировали, правка
пишется отдельной строкой с пометкой «правка».

**Расписание (по будням, МСК).** В 18:00 — одно сообщение в группу: «Товарищи, день
окончен — заполните, пожалуйста, отчёт», с упоминанием тех, кто ещё не сдал. В 20:00 —
тег через `@username` тех, кто не сдал (если сдали все, бот молчит). Слоты, время
которых прошло до старта процесса, не досылаются, иначе каждый редеплой дублировал бы
сообщение.

**Команды.** `/start` доступна всем, остальные — только супер-админам, в личке или
в группе:

| Команда | Что делает |
|---|---|
| `/add @username Имя` | добавить или переименовать |
| `/remove @username` | убрать |
| `/users` | список и кто сдал сегодня |
| `/sync` | перечитать таблицу (аккаунты и чат) |
| `/chatid` | id текущего чата — вписать в лист «Настройки» |
| `/remind`, `/check` | разослать напоминание или проверку прямо сейчас |

## Архитектура

```
reflect_bot/
  domain/          модели (Account, Report, IncomingMessage, TimeOfDay) и исключения
  interfaces/      контракты (ABC): репозитории, Messenger, UpdateSource, Alerter, Clock,
                   Reloadable, HealthIndicator
  infrastructure/  реализации: Google Sheets (gspread), Telegram Bot API, часы МСК, алармы
  services/        бизнес-логика: аккаунты, настройки чата, отчёты, напоминания, синхронизация
  bot/             команды (Command + CommandRegistry), обработчики (цепочка обязанностей),
                   диспетчер, long polling
  scheduling/      ScheduledJob и DailyScheduler
  app/             DI-контейнер (ApplicationContext), Infrastructure, жизненный цикл
  texts.py         все тексты бота
  main.py          FastAPI: lifespan + /health
```

- Сервисы зависят только от интерфейсов; конкретные классы создаются в одном месте —
  `ApplicationContext`, аналог `@Configuration` в Spring.
- Новая команда — это новый класс `Command` плюс строчка `register(...)`; новая задача
  по расписанию — новый `ScheduledJob`. Диспетчер и планировщик при этом не меняются.
- Вся блокирующая работа (gspread, Bot API) идёт через `SerialExecutor` в одном потоке.
  Апдейты и задачи расписания выполняются строго по очереди, поэтому кешам не нужны
  блокировки.

## Запуск

### Один раз

1. В Google Cloud включить **Google Sheets API**, создать сервис-аккаунт и скачать
   JSON-ключ.
2. Создать таблицу и дать email сервис-аккаунта права **редактора**. ID таблицы — кусок
   URL между `/d/` и `/edit`.
3. В @BotFather выключить у бота privacy mode (`/setprivacy` → Disable), затем удалить
   бота из группы и добавить заново — иначе в группе он видит только команды. Реакции
   в группе должны быть разрешены.
4. С этим токеном не должен работать ещё один `getUpdates`-процесс или вебхук, иначе
   Telegram отвечает 409.

### После деплоя

1. Написать в группе `/chatid` и вписать ответ в лист «Настройки».
2. Отправить боту `/sync`, затем добавить людей командой `/add @ivan_bel Белорус`.

### Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен бота |
| `SUPER_ADMIN_USERNAME` | да | ники супер-админов через запятую, с `@` или без: `@yan, @ivan_bel` |
| `GOOGLE_SHEET_ID` | да | id Google-таблицы |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | да | JSON-ключ сервис-аккаунта, как есть или в base64 |
| `TELEGRAM_ALERT_CHAT_ID` | нет | чат для алармов; не задан — алармы только в лог |
| `REMIND_AT` | нет | время напоминания, по умолчанию `18:00` |
| `CHECK_AT` | нет | время проверки сдачи, по умолчанию `20:00` |
| `MIN_REPORT_CHARS` | нет | минимальная длина отчёта, по умолчанию 30 |
| `MAX_ATTEMPTS` | нет | попыток на напоминание или проверку, по умолчанию 5 |
| `LOG_LEVEL` | нет | по умолчанию INFO |

`GET /health` возвращает статус (`STARTING`, пока таблица не загружена, затем `UP`),
`bootstrap_error` и состояние компонентов: таблица, отчёты, Telegram, расписание.

### Локально

```bash
pip install -r requirements-dev.txt
pytest
TELEGRAM_BOT_TOKEN=... SUPER_ADMIN_USERNAME=... GOOGLE_SHEET_ID=... GOOGLE_SERVICE_ACCOUNT_JSON="$(base64 -i key.json)" \
  uvicorn reflect_bot.main:app --reload
```
